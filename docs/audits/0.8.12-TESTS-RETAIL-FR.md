Préparé le 2026-11-15 pour le code actuel du dépôt. **Aucun résultat Retail n'est encore validé dans cette fiche.** La version reste 0.8.12; ce document ne constitue pas une publication ni une autorisation de mise en production.

Déploiement déclaré par l'utilisateur le 2026-11-15 via [deploy.ps1](../../scripts/deploy.ps1). Fichiers installés non revérifiés par l'agent; résultats en jeu en attente. Le commit local de consolidation ne ferme aucun test de cette fiche.

## Avant de commencer

- Installer le même candidat récent sur les deux clients, puis redémarrer complètement WoW pour charger les nouveaux fichiers et bibliothèques. Une ancienne installation peut afficher elle aussi « 0.8.12 » : vérifier la présence du nouveau diagnostic de capture dans PlayerUI → Grand coffre / Great Vault.
- Prévoir **A : membre qui réclame un objet**, **B : GM/Officer de la même guilde**, avec Dibs activé et la communication de guilde disponible. Le module Pre-Dibs doit être activé par la guilde pour enregistrer le coffre. Sortir du mode développeur pour ce test réel. Un Officer suffit pour la revue autorisée du coffre; prévoir le GM pour les changements de modules/politique, et le coordinateur comptable autorisé pour l'activation. À défaut, noter ces actions BLOQUÉES sans contourner leurs permissions.
- Noter `/dibs build` sur chaque client et le numéro du client WoW via `/run print(GetBuildInfo())`. Un identifiant de build identique ne prouve pas, à lui seul, que tous les changements non commités sont installés.
- Relever le solde et le nombre/liste de transactions visibles avant le coffre. Garder les messages d'erreur et captures; utiliser BugSack s'il est déjà installé ou `/console scriptErrors 1` pour afficher les erreurs Lua.
- **Faire les tests V01–V05 avant toute saisie manuelle.** Une récompense ne peut pas être réclamée deux fois pour refaire le test. Si elle a déjà été prise cette semaine, marquer le test automatique BLOQUÉ; un autre personnage avec récompense disponible peut servir.
- Pour les sections S et D, utiliser une guilde/environnement de test et sauvegarder les données avant toute action. Ne pas activer une saison, changer les rangs, désactiver un module de guilde, restaurer une sauvegarde ou publier une configuration expérimentale dans la guilde réelle pour compléter cette fiche. Sans environnement adapté : BLOQUÉ, pas RÉUSSI.

Pour chaque test, noter **RÉUSSI / ÉCHEC / BLOQUÉ / NON TESTÉ**. Un écran ou champ absent se note « non exposé »; ne pas inventer sa valeur.

## Priorité 1 — Grande chambre forte : à faire avant de prendre l'objet

### V01 — Capture disponible et identité du candidat

1. Sur A : `/dibs ui`, onglet **Grand coffre / Great Vault**.
2. Vérifier l'état de capture. Ouvrir ensuite la Grande chambre forte près du coffre réel, puis revenir sur la page Dibs.
3. Noter le nombre d'options d'équipement lisibles. Faire une capture des choix Blizzard et de l'état Dibs. Noter les compléments éventuels (clé mythique, monnaie, autre objet).

**Attendu :** capture active lorsque les API et le module sont disponibles. Le nombre concerne les options d'équipement identifiées, pas tous les objets supplémentaires. Aucune nouvelle acquisition ni transaction ne vient du simple affichage. Hors interaction ou avant chargement des données, zéro option lisible ne prouve pas une panne; relever le contexte. Si la capture est indisponible/désactivée au coffre réel, conserver la raison et ne pas considérer la prise automatique comme validée.

### V03 — Réclamer réellement la récompense choisie

1. Noter le nom et le lien exact de l'objet choisi, ses caractéristiques et son classement affiché. Garder le message de réception dans le chat.
2. Confirmer le retrait dans Blizzard. Vérifier l'objet reçu dans les sacs puis la page Grand coffre de Dibs, déjà ouverte si possible.
3. Survoler la ligne et noter date, source, état de confirmation et reset quand ils sont visibles. Cliquer l'objet pour comparer sa variante avec celui reçu.

**Attendu :** une seule acquisition pour l'équipement choisi, confirmée automatiquement, avec la bonne identité d'objet. Les choix non pris et une clé complémentaire ne sont pas ajoutés comme équipements pris. La page se rafraîchit et le dernier résultat confirme l'enregistrement. Le solde et les transactions Dibs ne changent pas. Si l'infobulle arrive en retard, l'adaptateur peut attendre les données dans la limite de son contexte de 120 secondes; un défaut doit produire une raison, pas une fausse confirmation. Une difficulté illisible reste un échec de capture automatique à documenter, même si une saisie manuelle permet ensuite de conserver l'objet.

**Attendu :** B reçoit une ligne cohérente avec A : membre, objet, date et confirmation. La synchronisation n'est pas nécessairement instantanée et un message « envoyé » ne prouve pas la réception. Aucun gain Dibs ni doublon n'est créé.
