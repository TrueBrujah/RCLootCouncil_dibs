# UI Help and Documentation Matrix

Scope: presentation/help inventory for Player, Officer, Guild Master, and Developer surfaces. Phase 2 disposition values identify whether a gap was resolved with `ADD_HELP`, `REUSE_EXISTING_HELP`, or `ADD_DOC_CONCEPT`; `TECHNICAL_ONLY` and `NOT_APPLICABLE` document intentional non-UI or unsupported behavior. `MISSING` identifies unresolved help. This matrix records reviewed UI clusters, not every dynamically generated row or every widget instance.
Phase 2 disposition: 35 reviewed groups; 33 improved or explicitly resolved, 0 open gaps, 1 already consistent, and 1 intentionally technical-only. Each of the seven Phase 1 follow-up rows below records its selected disposition in the Status column.

## Documentation Mapping Notes

- Player-facing help should link to `docs/player/PLAYER_GUIDE_EN.md` and `docs/player/MODE_EMPLOI_JOUEUR.md`; do not expose protocol state, hashes, or epoch details there.
- Officer operations and audit expectations map to `docs/officer/GM_OFFICER_GUIDE_EN.md`, `docs/officer/MODE_EMPLOI_GM_OFFICER.md`, `docs/officer/auditing.md`, and `docs/officer/configuration.md`.
- Guild Master setup and policy choices map to the installation, seasons/ranks, and synchronization sections of both Officer guides.
- Technical state and protocol invariants map to `docs/developer/sync-protocol.md`, `docs/developer/governance-bootstrap.md`, and `docs/developer/data-model.md`.
- UI tooltips remain concise. Longer procedures belong in the role guide; the tooltip should describe meaning, scope, authority, or consequence and point the reader toward the appropriate workflow.
- Legacy help-key disposition: `UI_HELP_ENCOUNTER` is `REMOVE` because no current source consumer exists; Encounter mode uses `UI_HELP_PREDIB_MODE`, and historical encounter evidence uses `UI_HELP_ENCOUNTER_EVIDENCE`. `UI_HELP_REASON` is `REUSE` at `Ledger.AdminAdjust` (`ledger.adjust.reason`). `UI_HELP_SETUP_ASSISTANT` is `REUSE` at `SetupAssistant.Evaluate` (`setup.assistant.readiness`).
- Raid Relay source distinction: `Dibs.RaidRelay.Broadcast` is Developer-only guild-state synchronization and has no proposal/confirm UI. `Dibs.RaidRelay.SendReminder` is separately exposed in RCLootCouncil options and has localized Officer/GM help; it sends chat text and does not record an award or change Dibs.
