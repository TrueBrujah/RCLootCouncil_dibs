# DIBS Retail Manual Validation Checklist

Status: Execution checklist for in-game World of Warcraft Retail validation. This document does not change addon behavior. Run against the exact Retail package under review and record its addon version/build, client version, test date, tester, guild, realm, client/account labels, and whether RCLootCouncil, BugSack, and BugGrabber are installed.

## Safe Test Setup

- Use a dedicated test account/character and disposable test guild wherever possible. Do not initialize, alter, or delete SavedVariables for a production guild as part of these tests.
- For Test 1, fully exit WoW. Back up the test account's DIBS SavedVariables, then remove or rename only the DIBS files for that test environment: `RCLootCouncil_dibsDB.lua`, `RCLootCouncil_dibsSandboxDB.lua`, and the per-character `RCLootCouncil_dibsLocalDB.lua` (including their matching `.bak` files if present). Preserve all unrelated addon files. Start WoW only after the backup/removal. Restore the backup after the test if the environment is reused.
- For Tests 6-7, use a separate copy of SavedVariables with real historical DIBS data. Keep the source copy untouched and prevent the test client from saving back to the source. Guild data is keyed by guild identity; verify the copied data is loaded for the intended test guild before acting. If that cannot be done safely, mark the test BLOCKED rather than testing against live data.
- Do not use hidden Lua/API calls to make a UI-only test pass. Record controls/data that the current UI does not expose as `NOT TESTABLE THROUGH UI` or `NOT EXPOSED`; do not treat those gaps as a successful observation.
- Automated baseline note: the reported full regression suite has one known pre-existing Pre-Dib heartbeat timer failure. This does not waive any Retail check below; record any new Retail errors independently.
