# Requests and loot workflow

Before an encounter, a player may use **I Wanna Dibs** or an Encounter Journal action to create a Pre-Dib request. The request is validated against the active season, item context, difficulty, and configured mode. Officers can review, confirm, invalidate, cancel, or fulfill requests.

When an item drops, RCLootCouncil may project the request and eligibility into its candidate view. RCLootCouncil decides the winner. Dibs does not award the item because a player has the highest balance. After a qualifying award is finalized by an authorized local Master Looter callback, the accounting path may consume one Dib and records award/evidence references.

Receiving loot alone, a boss kill, or a Vault acquisition does not consume a Dib. Vault acquisitions are display-only. If a historical RC row is ambiguous, use the reconciliation workflow in [auditing.md](auditing.md); do not create a ledger use from a list row without evidence and confirmation.
